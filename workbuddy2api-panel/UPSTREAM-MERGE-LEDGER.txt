1. 本轮有任何文件解析失败 → **只增不删**（半写文件被当成「文件已删」会把在池号踢掉，
   而剔除会写进 state.json，下次启动也不复活）；
2. 删除要连续 N 轮扫描都缺席，第一次只挂账；
3. 扫描前后各取一次目录签名，期间集合变动就放弃本轮（并给一次重试：LoadDirReport 自己
   会写盘回填 realm，首轮指纹几乎必然变一次）；
4. 剔除前再 stat 一次该账号文件，文件在就跳过（同时堵住「面板刚导入、重载还没看到」）。

另：轮询判据用**内容指纹**（uid|expiresAt|realm 有序哈希）而不是 mtime —— 回填 realm
会改 mtime，按 mtime 判会自激。

`c54c517` 的串行化一并落地：登录入池、导入入池、API Key 入池、账号移除都持 `reloadMu`，
与重载扫描互斥（锁序 `proxyAccountMu → reloadMu → pool.mu`）。

**本仓差异**：`LoadDir` 是我们的版本（缺 uid 跳过 + 同 UID 去重），`LoadDirReport` 按它
重构（缺 uid 也计入 ParseError，否则热重载会在「该文件本轮不可用」时删除同号）。

# 本仓增强（非上游）：账号类型人工定性 + 国际版任务入口

## 1) 「是否企业版」人工覆盖

自动判据看 `account.type` 与 `enterpriseId`，而国服个人号常带一个默认租户的
`enterpriseId`（曾把整批个人号判成企业版：签到 400「企业账号不支持该操作」、成长任务
403）。上游字段不可信时只能由人定性：

- `auth.EnterpriseOverride`：`""`（自动）/ `"enterprise"` / `"personal"`，`IsEnterprise()`
  里**优先于**自动判据；
- 落盘 `account.enterprise_override`（**同时读**旧扁平形态的顶层键与驼峰别名；
  清空时把两种写法都删掉，避免外部工具读成「显式设了空」）；
- `SaveAtomic` 本来就会「读回原文件、保留未知键、把扁平文件升级成嵌套形」，
  所以旧版本 JSON 不会因为切一次类型就丢字段（测试覆盖 `custom_note` 保留）；
- 面板：行内「类型」按钮循环 自动 → 强制企业 → 强制个人，`POST
  /panel/api/accounts/{uid}/enterprise`；非法值 400（不静默当自动判定）；
- `/status` 透出 `enterprise_override`，面板显示「企业（自动）/ 企业 / 个人」。

## 2) 国际版任务入口放回

此前 `GET /panel/api/accounts/{uid}/tasks` 对 global 直接 501 —— 用户视角就是入口丢了。
上游自己对国际区是「只读 schema」：能列任务，但接单/领奖/自动执行没有验证过的契约。

- 查询：照常 `ListTasks`，返回 `{realm, capabilities, tasks, message}`，其中
  `accept/claim/automate` 全 false；
- 查询失败（上游 404/403）：仍回 **200 + 空列表 + 说明**（含错误原因），不把面板整页
  渲染成错误；
- 写操作（accept / accept_all / claim / auto）：保持 501 + 「国际区任务暂仅支持查询」；
- 面板：行内「任务」按钮对国际版恢复渲染（企业版 / API Key 仍隐藏）；弹窗按
  `capabilities` 把按钮换成「只读」标签，并把 message 显示在标题旁。

## 修复：「强制个人」没生效 + 任务弹窗被拉长

1. **第二层判据没覆盖**：`IsEnterpriseSession()` = `IsEnterprise() || token_source==enterprise_switch`。
   首版只让 `IsEnterprise()` 尊重覆盖，于是企业切换令牌的账号改成个人版后，任务面板仍回
   「企业上下文账号不参与成长任务（上游会静默丢弃）」——用户看到的就是「改了但没用」。
   现在覆盖为 personal 时整层判据直接返回 false（定性是人对上游字段的否决，不该被
   token_source 再否决一次）；同时新增 `IsEnterpriseToken()` 只反映令牌事实，供调度器在
   「强制个人但仍是企业令牌」时留一行 WARN（上游可能 200 却静默丢弃，进度不动时这是唯一线索）。

2. **弹窗被拉长**：两处
   - 只读说明/失败原因塞进 `<h3>`，长文案把标题挤成两行 → 挪成 header 里独立一行，
     空时 `hidden`（空 div 也占一行高度）；
   - 弹窗写死 `width:940px`，手机 WebView（CSS 宽约 400px）里只能压窄 flex 项，
     5 个按钮被挤到几十像素宽、文字竖排成「一列字」→ 改成 `width:min(940px,96vw)`，
     并给 `.dlg footer` 加 `flex-wrap: wrap` + 按钮 `white-space: nowrap`（换行而不是压扁）。

### 关于 `golang.org/x/net/proxy`

构建环境拉不到 Go 模块（`proxy.golang.org` 与 goproxy.cn/io/阿里云镜像的 DNS 全部
`connection refused`），而 `internal/proxypool/transport.go` 只用到它的三个符号
（`Auth` / `SOCKS5` / `ContextDialer`）。为三个符号让整个包编译不过不值当，于是写了
`internal/proxypool/socks5.go`：CONNECT + RFC 1929 用户名口令认证，行为与 x/net 对齐
（目标按域名下发由代理解析、认证失败与 REP≠0 一律报错而不静默降级成直连、`DialContext`
受同一个 ctx 约束）。**这条替代也让本仓的 proxypool 变成零外部依赖**。

### 第十四批（已合：`b4012ceb` 续写闸门）

| 问题 | 修法 |
|---|---|
| 不带限额的请求被档位下限误伤 | 累计上限原先一律按「档位下限 × 4」算，而 Codex 这类每段就能写到上游单段上限（32000）：low 档 16384 比一段还小 → 一次都续不了。现在不带限额的**不按 token 封顶**，只看段数（`noLimitContinueSegments=3`，3 段 ≈ 3×32000 输出） |
| 带限额时累计上限口径 | 改为 `max(客户端限额, 档位下限) × 4`——额度 ≥32k 的「要长文」请求每段本身就有 32k，只按下限算的上限连一段都装不下 |
| 探活请求被续满 | `max_tokens<16` 的 key 探活出站不被抬额度，但思考占比一高就能续满 8 段（每段一次计费调用）。现在探活级额度一律不续 |
| 关不掉思考的模型白烧额度 | glm/hy3 这类「额度被抬过 / 思考吃光」时续写会拿同一份额度再烧一遍思考。这两条例外现在只在**思考关得掉**时才续；零正文形态交给 `starved.go` 的救援 |
| `budgetWasRaised` 口径 | 与出站 `upstream.ensureMinOutputBudget` 对齐：探活级额度、客户端自己关思考的请求出站不被抬，这里也不能算「抬过」 |

收口统一：`atSegmentCap()`（续写、盲重试、narration/starved/toolonly 三类救援共用一个判据）、
`outputCap()`（token 上限）、`limitedButContinuable()`（带限额时到底续不续）。

用例：不带限额 × 五档位都续满 3 段且只有一个终态；额度 32000 + low 档续 3 次；`budgetWasRaised`
七个分支；`outputCap` 四档。

**本仓分叉保留**：`features.tool_only_rescue`（默认关）与工具意图尾巴门控不动——那是本仓对
「agent 正常收尾被误判成截断」的处理，上游这套闸门不涉及。
